# AI Memory - Bongo Champs

- Stack: Electron (app) + `uiohook-napi` (global keyboard/mouse hook) + `ws` relay server in `server/`. Plain JS, no bundler.
- Rig layout: sprite positions in `src/renderer/overlay.css` were fitted pixel-wise against `bongo_champs.gif` (scale 1.327, head at gif (145.4,167)). All arm sprites are unrotated; up and down states have slightly different offsets.
- `-webkit-text-stroke` + `paint-order` renders patchy on HTML text in Electron/Chromium: use multi `text-shadow` outlines instead.
- Building: `npmRebuild: false` is required (uiohook-napi ships N-API prebuilds; cross-building Windows from a Mac otherwise fails with "node-gyp does not support cross-compiling").
- Mac universal build needs `mac.x64ArchFiles: "**/uiohook-napi/prebuilds/**"`, otherwise @electron/universal refuses identical arch files.
- Mac signing: ad-hoc (`identity: "-"`) breaks Accessibility on every update (TCC keys on the cdhash). Now: self-signed "Bongo Champs Signing" cert (files in `~/.bongo-champs-signing/`, imported in login keychain), applied by `build/sign-mac.js` afterPack hook with `mac.identity: null`, because electron-builder rejects untrusted identities. `codesign` itself accepts the untrusted cert by SHA-1. Keep `hardenedRuntime: false` (no Developer ID / notarization).
- macOS: the input hook needs Accessibility permission; `main.js` polls `isTrustedAccessibilityClient` and starts the hook once granted.
- Testing in this environment: `screencapture` is blocked; screenshot the overlay through CDP (`--remote-debugging-port=9333`, `Page.captureScreenshot`). The browser pane can preview `src/renderer/index.html` in demo mode (`.claude/launch.json` > overlay-demo).
- Server URL is baked from `package.json` `bongoServerUrl` (env `BONGO_SERVER_URL` overrides for dev).
- Production relay = `cloudflare/` (Workers + SQLite-backed Durable Object per session, Hibernation API, free plan). Clients connect to `<serverUrl>/room/<CODE>`; `server/` (Node) implements the same protocol for local dev. Keep both in sync.
- Network flush is 500 ms (`FLUSH_INTERVAL_MS` in session-client.js must equal `NETWORK_FLUSH_MS` in overlay.js) to stay within the Cloudflare free request quota.
- `settings.json` persists only `customServerUrl` (when the user typed one), never the default URL, so new builds can move everyone to a new server.
- `wrangler dev --port 8788` runs the Cloudflare relay locally; wrangler needs `allowScripts` for esbuild + workerd (set in cloudflare/package.json).
- Production relay deployed on 2026-10-15: `wss://bongo-champs.bongo-champs-cloudflare.workers.dev` (Madbox Cloudflare account, Workers Free). Redeploy with `cd cloudflare && npx wrangler deploy`.
- Never leave `node_modules/uiohook-napi/build/` around: node-gyp-build loads `build/Release` before `prebuilds/`, so a stale macOS binary there would ship inside the Windows installer. It's excluded in the electron-builder `files` list.
- Testing next to an installed copy: run the dev app with `BONGO_USER_DATA=<folder>` (own settings + own single-instance lock). Without it, the dev instance exits and forwards its `bongochamps://` argv to the installed app, which then joins the test session.
- Build size: ~99% is Electron/Chromium (Mac universal app 510 MB unpacked / 229 MB DMG, Windows 375 MB unpacked / 112 MB installer); our code + assets are ~1.5 MB.
- Overlay size scales live in `SIZE_SCALES` (overlay.js): small 0.7, medium 0.85, large 1 (native sprite size, sharpest). Size is local-only, set from the menu or Settings.
- Hats/Mojis/gacha: catalog in `src/catalog.js`, generic capsule rules in `src/gacha.js` (collections 'hats' and 'mojis', shared tokens, `CAPSULE_TAP_COST` = 2500 tap points stored in `points`, separate from `count`). Renderer gets `catalog` + `ownedMojis` via `publicState()`. Hat sprites use a 130x110 frame, brim center at (65,95); `.hat` CSS places it at stage (80,-62). Counters keep a fixed position and are drawn in front of hats; `.champ` has a fixed 36px top padding so the tallest hat is not clipped by the window. Tokens: 1 per hour of app open (`startPlayClock`, sleep not counted), 1 welcome token. No duplicates.
- Emojis: allowed list duplicated in overlay.js, server/server.js and cloudflare/src/index.js (keep in sync). Relay cooldown 1.5 s, client 2 s. In the Cloudflare DO, always spread the attachment (`{ ...attachment, peer }`) or `lastEmojiAt` is lost.
- Overlay clicks vs drag: interactive elements (emoji bar, gift badge, permission banner) are excluded from drag start in `isInteractive()`; a click without movement on the local stage toggles the emoji bar.
- macOS TCC attributes permission prompts to the *responsible process*: apps launched from Claude Code's shell (`npx electron`, or the app binary directly) register as "claude" in Accessibility. Launch an installed build with `open -a`/`open` so the prompt is attributed to Bongo Champs.
- A stale Accessibility entry (granted to an older signature) shows as ON but does nothing. Removing it with "-" in System Settings always works; `tccutil reset` (used by the Fix it button) may fail without admin rights, so the banner then shows the manual "-" instructions.
- Mojis: 76 released ones from the Figma file "PC - Pocket Board", page "Moji Renders", excluding sections "Old Mojies" and "NOT RELEASED" and placeholders. Figma exports come at mixed sizes (256 to 1024 px): normalize with `sips -Z 128`. Emoji messages carry Moji ids (`/^[a-z0-9-]{1,32}$/`) or a legacy unicode emoji from 1.1.0 apps; clients only render known ids.
- CDP testing: never `location.reload()` through cdp.js (it kills the session and hangs); relaunch the test instance instead. After a `wrangler deploy`, wait ~20 s before live tests (old version still served briefly).
- Settings window: tabs Champ / Hats / Mojis / Session, grids only rebuilt when collections change (profile events arrive every second while typing).
- Windows: one transparent window per Champ. Local Champ = `index.html` (overlay.js), each friend = `peer.html?id=<peerId>` (peer.js); shared helpers in `overlay-common.js`. Main routes 'peer-update'/'peer-emoji' to that friend's window only, and `syncPeerWindows()` opens/closes windows on 'session' events. Resize/drag/menu IPC act on `BrowserWindow.fromWebContents(event.sender)`.
- Positions: `bounds` (local) and `peerPositions[peerId]` store full bounds (x, y, width, height); saving only x/y made windows drift on every launch because fitting re-anchors to the bottom-right corner. `visibleBounds()` drops positions on unplugged screens.
